# Lecture Motion｜口播画面制作

把口播的机制做成观众看得见的过程。按口播拆拍 → 主体动效 → 解释层 → 角色与字幕 → 连播审片执行。同稿返修先打开已认可工程，在它的场景、渲染器和时间轴上修改。新稿先跑通一个关键段，再把已验证的动效做法扩展到全片。

**默认出画方式。** 主图以运动中的对象、图形和必要符号为主。顶部标题、系列名、章节号、装饰横线和说明小字留在分镜或预览页外。有口播稿就默认烧入底部纯黑字幕，1080 宽先用 42 px，长句按语义拆为单行。无录音时按临时口播节奏排字幕。有实录后按实际台词和停顿校准。仅在用户明确要求纯画面时关闭字幕。

## 1. 读稿并明确覆盖范围

- 接收完整口播或指定段落，确认受众、画幅、预期时长、视觉参考和已有素材。已经提供的决定直接沿用。缺少录音时，先用分段时间制作无声预演。
- 读完整份正文，列出口播实际包含的主张、例子、证据、比较、条件和结论。为每个需要解释的段落标出原稿锚点和承接它的镜头。开场、章节衔接和结尾也应在分镜上有安排。
- 拆分依据是观众何时需要认识新对象、理解新关系或转换视角。相邻句在解释同一事时沿用同一镜，可以改变焦点或状态。时长不足时，先定位矛盾段落和可压缩之处，由用户决定需保留的实质内容。
- 维护原稿事实边界。示意数值、简化模型与实测标注清楚。保留例外、适用条件和反例。公式、代码、图表使用同一组数据、名称和单位。

## 2. 确立视觉方向

- 从一个最能体现课程的段落着手，先定主体与字幕的位置，标明读者先看哪里、下一眼去哪。需要新的风格判断时，可以给一张关键帧和一段短动效用于比较，再把选中的方式扩展到全文。
- 以获确认的 40 秒样片为运动基准。主体移动距离明确，进入和落定利落，图解连续发展。竖屏默认 1080×1440，浅底搭配紫绿点色。其他项目可改色板、背景图、字体与场景比例。若用户已有画幅和字号偏好，以其要求为准。
- 让表现形式服从内容。程序机制可用对象流转和局部状态，实验可用同尺度对比与曲线，历史或故事可用时间、地点和人物关系，实操可用真实界面片段加定位标注。图、字和背景有层级，重点可借留白、大小或颜色突出。
- 从[课程镜头卡](references/shots.md)选手法。一个镜头可以把连续位移、路径展开、重点错峰和镜头聚焦组合起来，配合一个主要信息变化。默认先用视觉状态讲清过程。需要读具体数值、公式或代码时，让它在对应拍点占据主画面，或放进分镜供审核。

## 3. 写能直接制作的分镜

每镜至少写清原稿锚点、观众需懂的事、起始画面、主动作、落定画面、字幕或动作触发词、下一镜的承接点。有角色时预留出场时间和站位，用可选动作版本接入。

- **镜头衔接。** 用同一对象、轴线、焦点或轨迹从一镜带到下一镜。比较或换章节时，可用同位切换、局部放大后拉远或直接切到新视角。没有相关对象时，从新画面的核心信息建立新的观看顺序。
- **动作节奏。** 给主动作预备、运动、落定三段。用缓入缓出或轻过冲传达对象的速度和重量。同组对象需要表现顺序时，按关联或阅读方向错峰。动线到位之后留出时间读公式、比较结果或看出因果。
- **信息揭示。** 在讲到条件时显示边界，在讲到变化时让对象实际变化，在说到结论时保留结果。从局部放大回到全景，说明这一步处于整条流程的哪里。
- **角色入画。** 构图给角色的实际位移留出空间，让角色、主图解、字幕能同时看清。选动作版本即可，脚步、手势和表情在角色模块内完成。
- 用户要求先审核 Skill 或分镜时，交付相应文稿，在确认前停在文稿阶段。已有确认的返修范围按对应镜头执行。

## 4. 先跑通主体，再加解释层

先在同一画布连播关键段的前一镜、当前镜和后一镜。让对象沿清楚的路径移动，有可见的起点、终点与到位后的状态，镜头之间沿用它的位置或形状。确认移动幅度、焦点交接和落定时间后，把矩阵、公式、局部代码加在真正发生计算的拍点，并复查叠加后主体仍然清楚。同稿返修保留已获认可的运动节奏，逐镜对照基准。具体做法见[实现与审片](references/production.md)。

### 渲染器与时间轴

| 画面需求 | 可选实现 |
| --- | --- |
| 排版、代码、字幕、卡片与界面复刻 | HTML/CSS。用可控位移、裁切和局部高亮保持字形清晰 |
| 连线、流程、几何、图表与路径描边 | SVG。优先复用坐标和对象标识，让路径与标签一起过渡 |
| 大量图元、逐帧计算、频繁形变 | Canvas。把位置与状态写成时间函数 |
| 需要空间旋转或真实空间关系 | WebGL 或 Three.js。三维空间应帮助理解对象关系 |
| 真实操作、实景或素材结合图解 | 视频或图片作为图层，按预览时刻定位并叠加必要标注 |

可在同一镜混用图层，例如 SVG 有向图配 HTML 标签和 Canvas 数据流。先复用已验证的绘图函数与播放器。职责明显变化后再抽出章节或组件。颜色、背景、字体和安全区集中维护，有新画幅时按实际输出复查排版。

工作台使用 `window.DUR`、`window.render(t)`、`window.READY` 契约，HTML、SVG、Canvas 都可以参与绘制。渲染依赖传入时刻与已加载资源。独立交付可选与目标形式匹配的时间轴和播放器。章节多时由统一入口将全片时间映射到章节内时间，字幕和角色事件也引用同一组锚点。有音频时以真实录音定位动作。实现细节见[时间轴与审片](references/production.md)。

## 5. 预留背景、曦曦和配音

先用背景、课件主体、角色、字幕四层组织场景。换主题色或底图后复查对比度。角色可关闭，启用时用角色包的版本名、时段和可选站位接入。配音、字幕和画面事件用同一条时间轴，实际录音到位后用语义锚点校准。字段和启用方式见[接入约定](references/integration.md)。

## 6. 审片和交付

- 按稿件覆盖表核对正文各段。静音看流程能否辨认，按出片尺寸确认图形和必要符号可读，逐镜查掉标题、说明小字与装饰横线。字幕或代码开启时单独检查字形和读完所需时长。
- 看主动作开始、途中和落定，以及相邻章节的连续播放。高亮和标签随对象变化，焦点转移有可见原因。随机顺序回看同一时刻，确保预览和取帧行为一致。
- 核对真实性与阅读节奏。有音频时实际试听术语、数字和停顿，并检查语义锚点。实际导出后检查每个字幕段，按正常速度回看完整文件。与基准同稿时逐镜检查运动位移、镜头交接、信息密度和主体大小。
- 将源文件、播放入口、分镜、实际检查和当前版本交到对应画面目录。已确认版本可供对照，返修另出候选。网页任务产出写入指定的 `workspace/motion/`。
