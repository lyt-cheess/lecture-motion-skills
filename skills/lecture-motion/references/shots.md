# 课程镜头卡

先确定口播中的主动作，再选一到两种镜头表现。以下方法可以在同一对象上接续。

表里的名称用于选镜头。出画时用形状、运动、颜色和必要符号来表现，解释性文字保留在口播、分镜或用户开启的字幕里。

| 口播在解释什么 | 画面怎么做 | 审片时看什么 |
| --- | --- | --- |
| 信息经过多个步骤 | 让同一对象沿可见路线移动，到站时改变状态，下一镜从其终点开始 | 静音看也能辨认输入、过程、输出 |
| 一个输入产生多种结果 | 保留源对象，分支副本错峰穿过各自的处理模块；结果保留各自标签 | 源对象为何分开，每一路做了什么 |
| 匹配、读取、加权 | 固定查询对象，逐一连到候选；显示分数及权重，再让贡献随权重汇入 | 原始值仍可识别，权重与贡献比例一致 |
| 范围、条件、例外 | 先展示可见范围，再用遮罩、边界线或开关切换条件；保留同一查询位置 | 能区分被屏蔽、尚未存在和存在但低权重 |
| 两种模式的对比 | 沿用同一组对象与坐标，对齐前后状态；交替高亮改变的部分 | 差异来自条件变化，尺度与指标一致 |
| 并行与串行 | 同一时间基准上表现独立通道与依赖链；有依赖的步骤等待前序完成 | 重叠表示实际可并行，串行能看出等待原因 |
| 结构、层级和维度 | 从整体推近到当前部件，保持层级锚点；必要时展开矩阵的行列并标记索引 | 放大前后是同一对象，行列意义与尺寸一致 |
| 数学运算 | 公式按计算次序出现，当前项高亮并对应图上操作；结果回到原位置 | 公式的维度、归一化轴、输入输出一致 |
| 如何实现计算 | 在需要时显示几行代码；值或对象随当前执行步骤变化 | 代码可读，能解释图解中不直观的一步 |
| 趋势、数量与资源 | 同尺度画条形、时间线或曲线，显示基线与变化；区分假设值和测量值 | 数量变化对得上，坐标与单位清楚 |
| 累积、循环和停止 | 保留状态，每轮读入新结果并触发下一轮；停止条件实际终止动作 | 能看出什么被保留、什么新增、何时停止 |
| 回顾 | 把刚刚出现的对象收回总图，高亮一到三条差异；为角色到达目标留出路径 | 观众能把总结对回具体画面 |
| 真实操作或手工步骤 | 用原始界面或素材建立全景，推近当前操作点，操作发生后展示结果状态 | 能看到操作前后区别与真实反馈 |
| 空间、位置与路径 | 先建立固定参照物，再表现对象沿路线移动，必要时用局部放大解释阻挡或距离 | 方向与位置在镜头切换后仍能追踪 |
| 事件或人物故事 | 保持同一人物、地点或道具跨镜出现；用时间或位置变化交代处境变化 | 行动、反馈和因果按叙述次序出现 |
| 证据如何支持判断 | 用局部裁切突出相关段落或数据，让结论贴到对应证据；并列比较时统一标尺 | 画面能分辨原始事实和讲解者的推断 |
| 抽象概念或类比 | 先展示熟悉情形，再显式映射到讲解对象；在读者容易误会的位置补边界 | 类比能帮助理解，适用边界也能看到 |

迁移示例。讲“限流后才排队”时，让同一批请求经过门槛，标清被拒绝的请求与获准排队的请求。随后固定横轴，用时间线对比到达速度与处理速度，在队尾显示积压。队列长度随进入和离开改变。这个片段用对象移动、条件边界和数量变化即可。

非技术迁移示例。讲“同一场雨为何在两条街留下不同积水”时，用俯视图保持两条街方向一致，先展示同样的降雨，再跟着水分别进入绿地或汇入排水口。随后用同一比例尺比较水位，标清这是机制示意。
